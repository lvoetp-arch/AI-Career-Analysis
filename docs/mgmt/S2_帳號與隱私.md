- 分支：從最新的 `main` 開出 `s2-account-privacy`，只在此分支提交；不得直接提交到 `main`，不得 force push。

- 完成後把交接摘要（契約 §14 格式）存成 `docs/handoff/S2.md` 並提交；摘要中不得含個資或金鑰。你不需要自己合併分支，使用者審查後才合併。

## 做
**頁面**（`frontend/`）：
1. `index.html` 首頁，版型依《UI模板.png》：頂部列（標誌 + 登入／註冊）、主視覺標題與兩個按鈕（「丟履歷進來」→ 上傳或登入；「先看範例報告」→ `sample_report.html`，由 S7 提供，S7 完成前以停用狀態顯示）、「五步，就這樣」五張步驟卡、兩個示意卡（自評示意、報告示意）、頁尾。
   - **示意卡不得出現百分比分數**（契約 §10 第 9 條）；報告示意改用「證據：N 項充分／部分／不足」。
   - 頁面上要有一句明確聲明：輸出是方向探索建議，不是職缺保證。
   - **頁尾隱私文字必須準確**，用這段（可微調語氣，不可刪減內容）：「履歷文字會傳給 AI 供應商做分析；你確認資料後，原始檔案會立即刪除；你可以隨時刪除全部資料。」並連到隱私說明頁；字級不得小於 14px。
   - 不實作跑馬燈。手機版貼紙不旋轉、直向堆疊。
2. `login.html`、`register.html`：Email + 密碼，使用 Supabase Auth（supabase-js）；密碼規則與錯誤訊息（帳密錯誤、Email 已註冊、密碼太弱）用白話；成功後取得 token 並實作 `js/auth.js` 真實版本（保留 S1 的介面）。
3. `privacy.html` 隱私說明與同意：必須如實寫出——收集什麼、**不收集什麼**（契約 §10 清單）、履歷文字會傳給 LLM 供應商處理、原始檔在使用者確認資料後刪除、如何刪除自己的資料。同意以勾選 + 按鈕送出，記錄版本號。
4. `settings.html`：帳號資訊（只顯示 Email）、「刪除我的資料」區塊：列出將刪除的項目，需二次確認（輸入「刪除」）。

**API**：
- `POST /api/consents`、`GET /api/consents`
- `DELETE /api/me/data`：刪除該使用者的 Storage 檔案、resume_files、resume_profiles、career_inputs、analysis_runs、consent_records、usage_counters；保留 Auth 帳號（待決策 #4 的預設）。任何一步失敗要回報並可重試，不可部分成功卻回成功。
- 提供一個依賴函式 `require_consent(user)`：未同意最新版隱私說明則拋 `CONSENT_REQUIRED`（S3 會使用）。

**測試**：同意記錄、刪除後資料與檔案確實不存在、跨使用者無法刪除他人資料、`require_consent`。

## 不做
履歷上傳、確認、自評、分析；刪除帳號本身（Auth 使用者）。

## 驗收標準
- 註冊 → 登入 → 同意 → 登出完整可走；錯誤路徑（登入失敗、重複註冊）有明確提示。
- 刪除我的資料後，用 Supabase 直接查詢該 user_id 在所有表與 bucket 都是 0 筆。
- 隱私說明頁內容與契約 §10 一致（逐條對照）。
- 手機 360px 可完整操作。
