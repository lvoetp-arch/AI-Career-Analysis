> **狀態：S0 已完成並合併進 main（歷史紀錄，勿再使用）。** 實際成果見 `docs/handoff/S0.md`。契約以 `docs/00_總管理與共用契約.md` 為準。

## 工作環境與提交規則（本站必須遵守）
- 工作目錄為專案根目錄（`AI Career Analysis`，遠端 repo：`lvoetp3-cpu/AI-Career-Analysis`，私有）。環境為 Windows：指令請用 Windows 可執行的寫法（`python -m pytest`、`.venv\Scripts\activate`），不要寫 Linux 專用指令。
- 分支：從最新的 `main` 開出 `s0-foundation`，只在此分支提交；不得直接提交到 `main`，不得 force push。
- 只修改本站擁有的檔案（契約 §5）。需要動共用檔案時，不要自行改，寫進交接摘要。
- **絕對不可提交**：`.env`、任何金鑰（Supabase service key、Anthropic 金鑰）、真實履歷、`test-resumes/`、含個資的截圖或日誌。每次 commit 前先看 `git status` 與 `git diff --staged`。
- commit 訊息用繁體中文或英文皆可，一個 commit 做一件事；最後一個 commit 前，本站測試必須全部通過。
- 完成後把交接摘要（契約 §14 格式）存成 `docs/handoff/S0.md` 並提交；摘要中不得含個資或金鑰。你不需要自己合併分支，使用者審查後才合併。

00_總管理與共用契約.md、resume_profile.schema.json、analysis_result.schema.json

## 做
1. 專案骨架：依契約 §5 建立 repo 結構（空資料夾放 `.gitkeep`），`backend/app/main.py`（FastAPI、CORS 設定走環境變數、掛載 `frontend/` 靜態檔）。
2. `supabase/migrations/`：依契約 §6 建立全部資料表、索引、**RLS 政策**（`user_id = auth.uid()`），以及私有 bucket `resumes`（路徑 `{user_id}/{resume_file_id}.pdf`，禁止匿名與跨使用者存取）。
3. `core/config.py`：環境變數載入與驗證（SUPABASE_URL、SUPABASE_ANON_KEY、SUPABASE_SERVICE_KEY、ANTHROPIC_API_KEY、CLAUDE_MODEL、RATE_LIMIT_*、ALLOWED_ORIGINS）；缺少必要變數時啟動失敗並指出變數名稱。提供 `.env.example`。
4. `core/auth.py`：驗證 Supabase JWT，提供 FastAPI 依賴 `current_user`（回傳 user_id）；無效 token 回 `AUTH_FAILED`。
5. `core/errors.py`：契約 §9 的統一錯誤格式與全部錯誤碼；全域例外處理器；未預期例外回 500 通用訊息，不洩漏細節。
6. `core/db.py`：資料存取封裝。預設以「使用者 JWT」呼叫 Supabase 讓 RLS 生效；僅在刪檔、清理等管理操作使用 service key，且必須帶 user_id 條件。
7. `core/llm.py`：`LLMClient`（`complete(system, user) -> str`），逾時可設、呼叫失敗統一轉成 `LLM_ERROR`、**不記錄輸入輸出**、模型名稱取自 `CLAUDE_MODEL`；同時提供可注入的假客戶端供測試。
8. `core/ratelimit.py`：依 `usage_counters` 做每人每日限制（預設 parse 5、analysis 10，可由環境變數調整），超過回 `RATE_LIMITED`。
9. `core/logging.py`：日誌格式只允許記錄請求 ID、路徑、狀態碼、耗時、錯誤碼；提供測試確保日誌不含請求本文。
10. `GET /api/health`（不需登入）。
11. 測試：RLS 跨使用者讀寫必須被擋、錯誤格式、速率限制、health。

12. **版控防護**（第一個 commit 就要有）：`.gitignore`（至少排除 `.env`、`.venv/`、`__pycache__/`、`.pytest_cache/`、`test-resumes/`、`*.pdf`（避免誤提交履歷；確實要提交的文件 PDF 需用 `git add -f` 明確加入）、`test-resumes/` 只存在使用者本機，不進版控）、`.env.example`（只有變數名稱與說明，無任何值）、一個簡單的提交前檢查腳本 `scripts/check_no_secrets.py`（掃描暫存檔：金鑰樣式如 `sk-ant-`、`service_role`、台灣手機與 Email 格式、`test-resumes/` 路徑；命中則阻擋 commit），並在 README 說明如何啟用（Windows）。
13. 建立 `docs/handoff/` 資料夾（放 `.gitkeep`）。

## 不做
任何頁面、任何業務 API（consents、resumes、profiles…）、提示詞、UI。

## 驗收標準
- `supabase` migration 可重複套用；兩個測試帳號互相讀取對方資料全部失敗（RLS 測試通過）。
- 缺少環境變數時啟動訊息明確；`.env` 不進版控。
- 日誌測試通過（不含履歷內容）。
- README 說明如何本機啟動與跑測試。
- 故意在暫存區放入假金鑰字串與假手機號碼，檢查腳本必須阻擋（測試通過）。
