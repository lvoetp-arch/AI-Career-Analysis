# 分站 S9：整合測試與驗收（含展示準備）

## 工作環境與提交規則（本站必須遵守）
- 工作目錄為專案根目錄（`AI Career Analysis`，遠端 repo：`lvoetp3-cpu/AI-Career-Analysis`，私有）。環境為 Windows：指令請用 Windows 可執行的寫法（`python -m pytest`、`.venv\Scripts\activate`），不要寫 Linux 專用指令。
- 分支：從最新的 `main` 開出 `s9-qa`，只在此分支提交；不得直接提交到 `main`，不得 force push。
- 只修改本站擁有的檔案（契約 §5）。需要動共用檔案時，不要自行改，寫進交接摘要。
- **絕對不可提交**：`.env`、任何金鑰（Supabase service key、Anthropic 金鑰）、真實履歷、`test-resumes/`、含個資的截圖或日誌。每次 commit 前先看 `git status` 與 `git diff --staged`。
- commit 訊息用繁體中文或英文皆可，一個 commit 做一件事；最後一個 commit 前，本站測試必須全部通過。
- 完成後把交接摘要（契約 §14 格式）存成 `docs/handoff/S9.md` 並提交；摘要中不得含個資或金鑰。你不需要自己合併分支，使用者審查後才合併。

你是品質驗收工程師。前面各站都完成後，你負責端到端驗證、隱私與安全驗證、修正整合問題、準備展示。共用規則以《00_總管理與共用契約.md》為準。

## 做
1. **端到端測試**：註冊 → 同意 → 上傳 → 確認 → 自評 → 分析 → 報告 → 歷史／匯出 → 刪除我的資料。涵蓋 Word 文件 T01–T10 全部案例（逐項列出對應結果）。
2. **隱私驗證**（逐條對照契約 §10）：
   - 掃描資料庫所有表與 Storage，確認沒有電話、Email、住址、年齡等不收錄資料；
   - 攔截送往 LLM 的請求內容，確認已遮蔽；
   - 日誌檔不含履歷或 LLM 內容；
   - 確認後原始 PDF 已刪除；刪檔失敗情境能被清理；
   - 「刪除我的資料」後所有表與 bucket 皆為零筆；
   - 全站畫面與文字不得出現適合度百分比、錄取機率等未經資料計算的分數（含首頁、範例報告頁）；
   - 首頁頁尾與隱私說明頁對「履歷文字會傳給 AI 供應商」的描述一致且準確。
3. **安全驗證**：兩個帳號跨存取（RLS）、無 token、過期 token、惡意履歷／自傳（提示詞注入）、XSS 內容（履歷中含 `<script>`）、超大檔、速率限制。
4. **RWD 驗證**：360 / 768 / 1200 寬度走完整流程；觸控目標與鍵盤操作。
5. **穩定度**：5 份履歷各跑一次完整流程，記錄解析通過率、耗時、分析失敗類型。
6. **缺陷分級**：阻擋展示（必修）／影響體驗（建議修）／可延後；必修項目直接修正，並說明修了什麼。
7. **展示準備**：展示腳本（使用去識別化履歷）、可能被問的問題與回答（隱私、準確度、限制、成本）、已知限制清單（誠實列出：只支援文字型 PDF、姓名無法遮蔽、方向非保證等）。

## 不做

## 額外驗收（契約 v0.4）
- 上傳頁與隱私頁有「測試版本，請勿上傳真實個資」警告，隱私頁寫明實際供應商與免費額度性質。
- 範例履歷流程可完整走通；`PRIVACY_VERSION` 升版後使用者被要求重新同意。
- 用 6 份虛構履歷（含 R6 注入）跑完整流程；`manifest.json` 的 `pii_markers` 不得出現在任何送往 LLM 的文字。
- 網址代號化與公司／學校名稱代號化確實生效（以攔截的請求內容檢查）。
- 跑馬燈動畫 ≤ 5 秒後靜止（S2b 已改）。
- **全站沒有任何頁面從 CDN 載入 supabase-js**（搜尋所有 `frontend/*.html`），載入順序皆為 config.js → vendor → auth.js；沒有 `config.local.js` 時每頁都只顯示「尚未設定」提示、不丟 JavaScript 錯誤。
- 隱私頁寫到「分析階段公司與學校改代號」：以攔截的請求內容驗證 S6 真的做到。
