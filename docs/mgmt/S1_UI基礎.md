## 做
1. **設計規範** `frontend/css/tokens.css`，依《UI模板.png》（以下色碼是從截圖取樣的近似值，可微調，但需在交接摘要記錄最終值）：
   - 色彩：背景米色 `#F7F0DA`（可加淡點狀紋）、卡片面 `#FDFCF4`、墨色 `#100C08`、黃 `#E9F037`、粉 `#FFB3D7`、紅 `#F44123`、藍（小標籤）`#1879F9`。
   - 造型：2–3px 墨色實線邊框；硬陰影 4–6px 位移、**無模糊**；貼紙元件可有 ±1–2° 旋轉，僅限 ≥ 768px 的裝飾用途。
   - 字型：標題用 Noto Sans TC 900（超粗），內文 400/500；原稿字型未知，不必追求一致；字型堆疊見契約 §12，需有後備字型。
   - **對比度（已實測）**：墨字／米 17.1、墨字／黃 15.8、墨字／粉 11.8、墨字／紅 5.2 皆通過 AA；**白字／紅 3.73、白字／藍 4.08 未通過小字 AA**。因此：紅色按鈕文字用墨色，或文字 ≥ 18.66px 粗體才可用白字；紅色「不足」標籤用墨字；藍色小標籤改深藍或改墨字。
   - 另需定義間距、字級、狀態色（成功／警示／錯誤）。
2. **基礎樣式** `base.css`、**元件** `components.css`（**不使用 CSS 框架**，只用自訂 CSS 變數與 CSS Grid / Flexbox）：
   - 頂部導覽（手機收合）、5 步驟條（上傳 → 確認 → 自評 → 分析 → 報告，可標示目前步驟與已完成）
   - 按鈕（主要／次要／危險／停用／載入中）、表單欄位（含錯誤提示樣式）、檔案拖放區
   - 提示條（資訊／警示／錯誤／成功）、卡片、可收合區塊（手風琴）、確認對話框、Toast
   - 技能評分列（1–5 方塊按鈕，選中為墨底白字；手機 ≥ 44px，含說明提示）
   - 貼紙標籤、貼紙卡片（可旋轉版與不旋轉版）、進度條（黑框紅填；用於證據摘要，不用於分數）、主要按鈕（紅底 + 硬陰影）與次要按鈕（白底）
   - 證據強弱標籤（充分＝黃、部分＝粉、不足＝紅；必須有文字，不可只靠顏色）
   - 載入指示（不定進度）、空白狀態、錯誤狀態版型
3. **前端模組**：
   - `js/api.js`：fetch 封裝；自動帶 Bearer token；將後端統一錯誤格式轉成可顯示的訊息；逾時處理（可設定，分析頁會用 90 秒以上）；401 時導向登入。
   - `js/ui.js`：`renderState(container, 'loading'|'empty'|'error'|'success', ...)`、toast、確認對話框、安全渲染（只用文字節點，不用 innerHTML 插入動態內容）。
   - `js/auth.js` **只留介面與假實作**（`getToken()`、`isLoggedIn()`、`logout()`），真正的 Supabase 登入由 S2 完成。
4. `frontend/ui-kit.html`：元件展示頁，手機 / 平板 / 桌面三種寬度都能檢視；包含各元件的所有狀態。

## 不做
跑馬燈（不實作，除非主 session 另行通知）；登入頁、任何業務頁面、與後端 API 的實際串接（只做 api.js 工具）。

## 驗收標準
- ui-kit.html 在 360 / 768 / 1200 寬度下不橫向捲動、無破版（含旋轉貼紙在 768 以下不旋轉）。
- 所有文字／背景組合附對比度表，皆 ≥ AA（4.5:1，大字 3:1）。
- 設有 `prefers-reduced-motion` 規則。
- 鍵盤可操作所有互動元件；焦點樣式可見。
- 步驟條、技能評分列、證據強弱標籤三個元件都有手機與桌面版本。
- 不出現 localStorage 儲存履歷資料；不用 innerHTML 插動態內容。
