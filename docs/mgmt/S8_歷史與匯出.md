# 分站 S8：歷史清單與匯出（借自完整版，可選）

## 工作環境與提交規則（本站必須遵守）
- 工作目錄為專案根目錄（`AI Career Analysis`，遠端 repo：`lvoetp3-cpu/AI-Career-Analysis`，私有）。環境為 Windows：指令請用 Windows 可執行的寫法（`python -m pytest`、`.venv\Scripts\activate`），不要寫 Linux 專用指令。
- 分支：從最新的 `main` 開出 `s8-history-export`，只在此分支提交；不得直接提交到 `main`，不得 force push。
- 只修改本站擁有的檔案（契約 §5）。需要動共用檔案時，不要自行改，寫進交接摘要。
- **絕對不可提交**：`.env`、任何金鑰（Supabase service key、Anthropic 金鑰）、真實履歷、`test-resumes/`、含個資的截圖或日誌。每次 commit 前先看 `git status` 與 `git diff --staged`。
- commit 訊息用繁體中文或英文皆可，一個 commit 做一件事；最後一個 commit 前，本站測試必須全部通過。
- 完成後把交接摘要（契約 §14 格式）存成 `docs/handoff/S8.md` 並提交；摘要中不得含個資或金鑰。你不需要自己合併分支，使用者審查後才合併。

## 你的角色
你負責「我的紀錄」：過去的分析清單與匯出。**這一站是可選的**——若主 session 通知期限緊迫，會直接略過。共用規則以《00_總管理與共用契約.md》為準。

## 附檔
00_總管理與共用契約.md、analysis_result.schema.json、S7 的報告頁（`report.html`）、ai_career_compass_sitemap_v2.png

## 做
1. `GET /api/analyses`：只回本人的清單，依時間新到舊，每筆含時間、狀態、三個方向名稱。
2. `frontend/history.html`：清單 → 點入 `report.html?id=…`；空白狀態（尚無分析）引導回首頁；失敗的分析以灰色標示並可重試（導向 analyzing）。
3. 匯出報告：**先採「列印樣式表」方案**——為 `report.html` 補 `@media print` 樣式（隱藏導覽與按鈕、展開所有方向、避免斷頁切在卡片中間），由使用者用瀏覽器「列印成 PDF」。只有在列印方案不可行時才改做伺服器端 PDF，且必須先向主 session 報告原因（伺服器端產生含中文字型的 PDF 容易出問題，需要額外處理字型與部署）。
4. 啟用 S7 預留的「歷史」「匯出」按鈕。

## 前端載入規則（契約 §12）
每個需要登入的頁面，script 順序固定為 `js/config.js` → `vendor/supabase-js-2.45.4.umd.js` → `js/auth.js`；不得從 CDN 載入 supabase-js。

## 不做
修改報告內容、分析邏輯。

## 驗收標準
- 兩個帳號互相看不到對方的清單（測試）。
- 列印預覽在 A4 下完整、中文無亂碼、未出現使用者介面按鈕。
- 手機上清單可正常瀏覽。
