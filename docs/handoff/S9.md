# S9 整合驗收報告

## 結論

應用程式在本機以虛構資料和服務替身走完整流程。公開部署驗收、真實 Supabase 跨帳號隔離及多份履歷的真實模型穩定度仍待驗證。此分支由尚未合入 main 的 S8 接續，供整合檢閱。
全套測試 353 項通過，13 項真實 RLS 測試因未配置專用帳號而略過。

## 隱私與資料驗證

- 攔截解析輸入，確認虛構姓名和 Email 標記未出現。既有 S3 測試涵蓋網址代號、人口資料及聯絡方式遮蔽。整合測試截取分析輸入，確認公司與學校代號化。抽查測試資料庫與事件日誌確認所用個資標記未留下。
- 私有 bucket 模擬測試確認原檔上傳後存在、確認時刪除、服務暫時失敗後可重試。刪除所有資料的測試涵蓋各使用者資料表與 bucket。
- 登入頁、首頁、隱私說明與其他共用頁尾一致揭露 AI 供應商及原檔刪除時機。上傳與隱私頁保留免費額度測試警告。新版隱私版本為 2026-11-23，舊版同意需重新確認。
- 全部使用 Auth 的 HTML 由本地 vendor 載入，順序為 config → vendor → auth。範例報告免登入。首頁與報告只顯示證據數量。
- 本機測試涵蓋缺少 token、Supabase 回報 token 無效、限額、模型輸出拒絕及來源標籤以文字渲染。模型對指定 R6 的實測仍待 fixture，診斷輸出只記驗證規則。

## 缺陷與處置

| 分級 | 處置 |
|---|---|
| 阻擋舊報告連結 | 修正登入流程丟失報告 ID 和自評 ID，只允許合法 UUID 的同站跳轉。 |
| 隱私提示與實作不符 | 確認頁、隱私說明和頁尾修正為刪除失敗可手動重試，前後端同步升版。 |
| 展示入口 | 啟用首頁既有範例報告連結，驗證首頁原有的四秒跑馬燈，移除 UI 元件展示頁無用的 Auth/API 腳本。 |
| 真實模型服務 | 本次虛構 PDF 解析成功，但分析階段收到 Gemini 429，供應商重試後仍失敗。已驗證替身流程，五至六份真實模型穩定度未完成。 |
| 待主 session | 公開 HTTPS、兩個專用 Supabase 測試帳號、R1–R6 與 marker manifest、免上傳範例履歷、自評預填、唯一索引及其餘既有補修事項。 |

API 形狀沒有改動。為修正整合缺陷，本分支調整了既有共用前端、隱私版本及對應測試。

## 展示腳本

1. 從首頁按「先看範例報告」，展示三個方向、證據理由與 30／60／90 天行動。
2. 用專用測試帳號登入並同意新版隱私說明，選擇虛構且可選取文字的 PDF。
3. 確認後展示原始 PDF 刪除結果，自評技能，再進入分析與報告。遇到供應商限流時可用該帳號已完成的報告展示。
4. 開啟歷史紀錄及「匯出 PDF」。用專用測試帳號展示刪除資料後歷史清單變空。

展示問答。分析方向供探索，自評和證據分開。測試環境使用免費模型，可能遇到限流，真人使用前需完成付費與隱私要求。系統只支援文字型 PDF，姓名遮蔽依輸入寫法，測試僅用虛構資料。
