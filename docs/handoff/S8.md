# S8 交接摘要

## 完成項目

- 新增 `GET /api/analyses`，透過身分驗證及帶有使用者條件的 Db 查詢列出本人分析，按開始時間由新至舊排列。
- `frontend/history.html` 顯示方向名稱、時間與狀態。已完成的紀錄連到報告，失敗的紀錄可使用原自評重試。空清單提供首頁入口。
- 報告頁啟用「歷史紀錄」與「匯出 PDF」。匯出使用瀏覽器列印，A4 會展開三個方向與證據來源，隱藏操作按鈕，並盡量避免在單張內容卡中間斷頁。

## API 與契約

歷史回應為 `[{analysis_id, created_at, status, directions, career_input_id}]`。完成紀錄的 directions 是方向名稱陣列，未完成時為空。career_input_id 為額外欄位，供失敗後重試。主 session 可將此欄位補入共用契約。

採用本站規格的瀏覽器列印方案，請將契約中的 `GET /api/analyses/{id}/export` 更新為既有報告頁的列印操作。本分支從尚未合入 main 的 s7-report 接續，並修改 S7 預留操作列及列印樣式。

## 待驗證

- 兩個模擬帳號已驗證 API 會帶各自的身分與擁有者條件。實際 Supabase 跨帳號測試仍需兩個專用測試帳號。
- 既有首頁範例入口與免上傳範例履歷維持 S7 交接中的待辦。

## 執行與驗證

```powershell
.\.venv\Scripts\python.exe -m pytest backend/tests/s8 -ra
.\.venv\Scripts\python.exe -m uvicorn app.main:create_app --factory --app-dir backend --reload
```

在既有報告使用「歷史紀錄」與「匯出 PDF」。Chromium 已驗證 360 px 的歷史清單、報告及重試連結、空清單和四頁 A4 範例 PDF。PDF 可擷取中文與三個方向的內容，且未包含介面按鈕。全套測試 351 項通過，13 項實際 RLS 測試略過。
