## 2. API 實際形狀與契約的差異

- `POST /confirm` 回應多一個欄位 `profile_id`：`{profile_id, status:"confirmed", original_file_deleted}`（契約只有後兩者）。
- `VALIDATION_ERROR` 的 `details[].path` 用與 `missing_flags` 相同的寫法，例如 `work_experience[0].gender`、`basics.phone`、頂層多餘欄位直接是 `phone`。`message` 是固定中文，**不含使用者輸入的值**（不用 jsonschema 原生訊息，避免回顯履歷內容）。
- `PUT` 的 body 除了 `parsed_json` 以外的任何鍵一律拒絕（path 為該鍵名）。
- 另有兩項 Schema 之外的檢查：`parsed_json` 序列化後超過 200,000 字元拒絕；`basics.links[].url`、`projects[].url`、`portfolio[].url` 若為 `javascript:`／`data:`／`vbscript:`／`file:`（會先去掉空白與控制字元再比對）拒絕。網址格式的嚴格檢查只在前端（http／https）。
- `{id}` 不是 UUID 一律回 `NOT_FOUND`。
- `GET /latest` 回最新一筆（依 `created_at`），不論狀態。沒有資料回 404 `NOT_FOUND`。
- `confirm` 行為：
  - 已 `confirmed` 者再按：不改 `confirmed_at`，只重試刪檔。
  - 檔案紀錄不存在或 `resume_file_id` 為空：視為沒有原始檔，`original_file_deleted: true`。
  - 檔案狀態已是 `deleted`：不再呼叫儲存層，回 `true`。
  - 刪檔失敗（含 S3 函式內部再拋例外）：確認照樣完成，回 `false`，檔案狀態為 `delete_failed`，下次再按確認會重試。
- `router` 的 `prefix="/api"` 與 S3 相同；若 `main.py` 已統一加前綴，兩邊都要拿掉。

## 4. 未完成或已知問題

- 「確認並繼續」之後的下一步按鈕連到 `assess.html`（S5），目前該頁不存在，點下去是 404。S5 完成後在 `review.js` 檔頭的 `NEXT_PAGE` 確認或修改。
- `upload.js` 的「檢查結果」按鈕只做了語法與修改範圍檢查，沒有自動化測試，也沒有實測（需要解析超過 100 秒才會出現）。
- `GET /latest` 無法分辨「這是不是本次上傳產生的」：若逾時前就已有一筆未確認的舊 draft，「檢查結果」會導向那一筆。
- `missing_flags` 的提示標籤：有 `id` 的項目跟著 `id` 走；沒有 `id` 的項目（`certifications`、`languages`、`basics.links`、`autobiography.sections`）以載入時的索引為準，刪除前面的項目後標籤可能對不上位置（只影響提示位置，不影響資料）。
- 使用者補上欄位後，前端不再顯示對應的警示標籤，但資料裡的 `missing_flags` **原樣保留、不更新**。S5／S6 若要使用 `missing_flags`，需自行判斷是否已補。
- 勾選「目前仍在這份工作」會清空並鎖定該筆的結束日期。
- 不顯示也不編修：`skills[].years_text`（規格：不提供年資相關欄位）、`source_text`、所有 `id`、`linked_ids`、`related_project_ids`、`related_project_id`、`url_truncated`、`parse_notes`、`language`、`schema_version`。
- 刪除專案時，會自動清掉經歷的 `related_project_ids`、專長的 `linked_ids`、獎項的 `related_project_id` 對它的引用。
- 後端測試使用假資料庫，沒有對真實 Supabase 做整合測試；Storage 檔案消失與 `resume_files.status = deleted` 由人工在真實環境驗證。
- 前端自動化檢查（jsdom，29 項）不在 repo 內。
- S3 `delete_original_file` 只攔 `AppError`；若成功刪檔後「標記 `deleted`」的更新拋出 `AppError`，例外會冒出。`profiles.py` 已在外層包住並補標 `delete_failed`，不影響使用者，但 S3 可考慮自行處理。

**人工驗證（使用者於本機完成）**：以虛構履歷上傳後自動導向確認頁；360px 寬度下各區塊可操作、無橫向捲軸；警示標籤點擊可跳轉；有未儲存變更時離開頁面會提醒；確認前有刪除原始 PDF 的提示；確認後 `resume_files.status` 為 `deleted` 且 Storage 檔案消失。
