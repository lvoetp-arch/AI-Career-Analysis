## 2. API 實際形狀與契約的差異
無。請求 `{profile_id, goal, skill_ratings[{skill_id,name,rating,source}], preferences}`，回應 200 `{career_input_id}`。
補充行為（契約沒寫到的細節）：
- `profile_id` 格式不對、不存在、不是本人 → `NOT_FOUND`；存在但未 `confirmed` → `VALIDATION_ERROR`（`path: profile_id`）。
- `rating` 只收 1–5 的整數；`0、6、3.5、3.0、"3"、true、null` 皆拒絕。
- `source=resume` 的 `skill_id` 必須存在於該 profile 的 `skills`，存檔時 `name` 以履歷內名稱為準；`source=added` 的 `skill_id` 必須為 null。
- 技能名稱（NFKC、忽略大小寫）不可重複；自加 ≤ 10 項、總數 ≤ 30 項；`skill_ratings` 可為空陣列。
- `preferences` 內任一字串 ≤ 200 字、任一陣列 ≤ 20 項、整體 ≤ 20,000 字元；不允許 Schema 沒有的欄位。待遇只存使用者填的原文／區間。
- `career_inputs` 只存 `{skill_id,name,rating,source}`，**不複製履歷證據**；自評與證據在頁面上分開呈現，文案不稱自評為已證實能力。

## 6. 如何本機執行與測試（Windows PowerShell）
```
.venv\Scripts\activate
python -m pytest backend/tests/s5 -q
python -m pytest backend/tests -q
python -m uvicorn app.main:create_app --factory --app-dir backend
# 登入後走完 上傳 → 確認 → 前往下一步（assess.html）

# 選用：登入時序測試需要 node 與 jsdom（沒有就會 skip）。jsdom 裝在專案外，不會弄髒 repo：
npm install --prefix $env:TEMP\s5-jsdom jsdom
$env:NODE_PATH = "$env:TEMP\s5-jsdom\node_modules"
python -m pytest backend/tests/s5/test_s5_auth_gate.py -q -rs
```
真瀏覽器驗證步驟：登入 → 上傳 → 確認 → 前往下一步 → 自評頁載入技能列表 → 評 2–3 項 → 下一步 → `PUT /api/career-inputs` 回 200 → 在 Supabase 以回傳的 id 查得到 `career_inputs` 列。jsdom 不能取代這一步。
