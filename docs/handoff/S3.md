## 5. 遮蔽規則仍會漏的項目（誠實列出）
- 寫在自傳句子裡的年齡、婚姻、家庭狀況（如「我是 34 歲的媽媽」）。
- 沒有「路／街／大道」的地址（只寫社區名、地標）。
- 沒有常見網域後綴的個人網址；沒有「LINE」標籤的單獨帳號。
- 姓名只擋使用者填的寫法：暱稱、別名、只寫姓氏（「林小姐」）、拼音不同寫法不會遮；留空時姓名會原樣送出。
- 公司名、學校名在 S3 階段仍會送出（S6 才代號化）。
- 以上 6 份虛構履歷的 `pii_markers` 在送出文字中零命中（已用程式比對送出前文字），但這不代表真實履歷也一樣。

## 7. 其他需主 session 決策或注意
- `core/llm.py` 把金鑰無效（401）、額度用完（429）、過載（503）全轉成同一個 LLM_ERROR，排查很費時；建議日誌只記 HTTP 狀態碼（不含內容）。
- `core/llm.py` / 契約：預設模型 `gemini-2.5-flash` 對新帳號已停用，需更新預設值與 `.env.example`；503 只重試一次且僅等 1 秒，尖峰時段不足。
- 免費額度有限，實測請集中執行；正式對外前依契約 §10-11 改付費方案。
- 自傳中的注入文字會原樣留在 parsed_json 的 autobiography：S4 顯示須用文字節點；S6 須把自傳當不可信資料。
- 前端逾時 100 秒；後端最壞情況（第一次 Schema 不符再呼叫一次）可能更久，使用者端會先逾時。
