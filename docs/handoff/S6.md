# S6 交接摘要

## 完成項目

- 新增分析 API 與等待頁，沿用 S5 的 career_input_id。等待頁先確認登入，送出後顯示實際等待秒數。同步回應或輪詢成功後導向報告頁，失敗可重試或返回自評。
- 以確認版履歷與 S5 輸入建立快照，移除 missing_flags 和 parse_notes。送給 LLM 的副本會代號化公司、學校、網址，並遮蔽可辨識的聯絡資料。快照留在受 RLS 保護的分析列，供歷史報告引用原始證據路徑。
- 實作 90 秒 LLM 時限、JSON Schema 與證據路徑驗證、一次修正重試、禁用主題掃描、速率限制及失敗狀態。完整提示詞見 [SYSTEM_PROMPT](../../backend/app/services/analysis/result.py)。
- 分析 ID 由使用者、自評 ID 與快照內容決定，既有主鍵負責跨程序的同份輸入競爭。失敗或超過 150 秒仍在執行的分析可用條件更新重新取得執行權。重試沿用分析 ID，attempts 記錄本次執行呼叫分析模型介面的次數。無新增 migration。

## 驗證

- Python 測試共 345 項通過，含 S6 新增的 8 項。缺專用測試帳號的 13 項 RLS 整合測試略過。
- 本機 Chromium 以 360 px 和測試 API 回應檢查缺少自評 ID、逾時、返回修改、重試、輪詢與成功導向。
- Gemini 測試只使用虛構資料，未送出專案中的履歷 fixture。首次三次嘗試中兩次未通過輸出解析、一次逾時。診斷確認回應使用 Markdown JSON 圍欄，解析器現在接受單一完整的 JSON 圍欄並保留後續驗證。修正後以同一份虛構資料重跑三次，兩次通過、一次在兩次輸出後仍未通過驗證。通過結果皆涵蓋 Python 資料自動化、營運數據分析與初階後端開發。
